Use case: THROWAWAY FORECASTING SCENARIO
  — Short-lived branch (2 hours) created solely for an isolated what-if analysis.
  — Represents a demand-spike forecast that MUST NOT affect production data.
  — Branch is discarded automatically at TTL expiry.

What was done on forecast-2x-demand branch:
1. Branch created from production with 7200s TTL (2h = short-lived throwaway)
2. Forecasting query run in isolation (see forecasting_branch.json for full output):
   - Scenario: "What if demand for SKU-APP-04412 doubled?" (2x demand spike)
   - Query: SELECT store_id, ..., lost_sales_exposure_usd AS current_exposure,
            ROUND(lost_sales_exposure_usd * 2, 2) AS forecast_2x_exposure
            FROM public.gold_open_shortfalls
            WHERE product_id = 'SKU-APP-04412'
            ORDER BY forecast_2x_exposure DESC LIMIT 10
   - Result: 10 stores, top exposure STORE-0034 at $153,668 (2x of $76,834)
3. Production verified unaffected: forecasting query ran on the branch only.
4. Branch expires automatically at 2026-08-27T15:48:09Z — no cleanup needed.

KEY DISTINCTION between the two branch types:
  dev-otto            → 7-day TTL, development iteration, migration development + validation
  forecast-2x-demand  → 2-hour TTL, throwaway forecasting, isolated what-if analysis
